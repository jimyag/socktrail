# 协议识别与按连接抓包计划

状态：本轮功能已实现并通过单元、race、vet、构建、受控本机 TCP/UDP 抓包验证；跨接口非对称流量、真实 OpenVPN/QUIC 会话和高负载下的健康指标仍需实机验收。结果见 [验证记录](validation.md)。

目标：在现有 IP 字节、PID socket I/O 和 HTTP Host/TLS SNI 口径之外，增加可验证的应用协议标签、TCP 健康指标，以及用户主动触发的短时 PCAPNG 抓包。

1. 在报文解码后按完整特征识别应用协议，保留 `unknown` 和识别依据；UDP 负载只在内存中短时使用。HTTP/TLS 沿用已有有界 TCP 重组，以它们的解析结果为准。测试分段、误报和端口冲突。协议标签不产生域名或 HTTP 请求数。
2. 从 TCP SYN/SYN-ACK 时间差生成带口径的握手 RTT 样本，并按有界序号区间记录观测到的数据重传。仅使用被选采集接口的数据，捕获中途开始或缺包时显示未知。对乱序、重复 SYN、重传与元数据合并做测试。
3. 在连接详情中启动限时、限大小的 PCAPNG 录制，按选中五元组、TCP 代次和单一采集接口过滤。文件包含原始以太网帧及尽力而为的 PID、协议、域名注释（tun 类接口的帧没有链路层头，写入时补一个空以太网头）；PID 事件迟到时注释可为未知。程序默认不保存正文，用户主动抓包才写入文件。用独立解析器验证文件格式，确认退出和超限后关闭文件。
4. 更新 TUI、README、验证记录并在目标 Linux 上核对生成的抓包和 RTT/重传口径。

依赖决策：应用协议识别先使用有界、少量本地特征解析，避免引入完整 DPI 框架及其无法满足的跨包假设；PCAPNG 使用格式规范中的 SHB、IDB、EPB 和标准注释选项实现最小写入器，不引入 tshark 运行依赖。若抓包接口无法提供可用的完整原始帧，停止导出切片并调整采集路径，不生成仅有统计字段的伪 PCAP。PCAPNG 规范：[IETF 草案](https://datatracker.ietf.org/doc/draft-ietf-opsawg-pcapng/)。
